## Overview

The dashboard is currently public — anyone with the URL can see client data. Each client deployment (Midnight Express, Professional Towing, Demo) points to its own Supabase project. We need authentication so only invited users can access their client's dashboard. No signup, no roles — users are created manually in Supabase Dashboard.

**Auth method:** Email + Password via `supabase.auth.signInWithPassword()`
**User creation:** Manual via Supabase Dashboard (Authentication → Users → Invite User)
**Session management:** Cookie-based via `@supabase/ssr`

```
     (own users)    (own users)    (own users)
           │              │              │

```

### Key Principle

- Each Supabase project has its own auth — users are naturally scoped to their client
- No cross-deployment user sharing — users exist only in their client's Supabase project
- Auth cookies include the project ref, so no cookie collisions between deployments

## Implementation Steps

### Step 1: Install `@supabase/ssr`

```bash
npm install @supabase/ssr
```

No other packages needed. `@supabase/supabase-js` v2.97.0 is already installed and compatible.

### Step 2: Create Supabase client utilities

**`lib/supabase/browser.ts`** — Browser client for "use client" components
- Uses `createBrowserClient` from `@supabase/ssr`
- Replaces current `lib/supabase.ts` singleton
- Automatically handles cookie-based sessions in the browser

**`lib/supabase/server.ts`** — Server client for Route Handlers
- Uses `createServerClient` from `@supabase/ssr` with `cookies()` from `next/headers`
- Used in `app/auth/callback/route.ts` for code exchange

**`lib/supabase/middleware.ts`** — Middleware helper
- Creates client that reads/writes cookies on request/response
- Calls `supabase.auth.getUser()` to refresh session (validates JWT server-side, not just local decode)
- Route guard logic: no user + not on `/login` or `/auth` → redirect to `/login`
- Already logged in + on `/login` → redirect to `/updates`

### Step 3: Update `lib/queries.ts`

- Change `import { supabase } from "./supabase"` → `import { createClient } from "./supabase/browser"`
- Each query function calls `const supabase = createClient()` at the top
- All query logic stays identical — only the client instantiation changes

### Step 4: Delete `lib/supabase.ts`

No longer needed — replaced by `lib/supabase/browser.ts`.

### Step 5: Create `middleware.ts` at project root

- Calls `updateSession()` from `lib/supabase/middleware.ts`
- Matcher excludes static assets: `_next/static`, `_next/image`, `favicon.ico`, `pvt-logo.png`, image files

### Step 6: Restructure app directory with route groups

**Before:**
```
app/
├── layout.tsx        (has TopNav + Footer)
├── page.tsx          (redirect to /updates)
└── updates/page.tsx  (dashboard)
```

**After:**
```
app/
├── layout.tsx              (bare: html/body/fonts only)
├── globals.css
├── (auth)/
│   ├── layout.tsx          (bare, no nav)
│   └── login/page.tsx      (login form)
├── (dashboard)/
│   ├── layout.tsx          (TopNav + Footer wrapper)
│   ├── page.tsx            (redirect to /updates)
│   └── updates/page.tsx    (dashboard)
└── auth/
    └── callback/route.ts   (not in a group — it's a Route Handler)
```

Route groups `(auth)` and `(dashboard)` don't affect URLs. `/login` and `/updates` work as expected.

### Step 7: Build login page — `app/(auth)/login/page.tsx`

See **Login Page Design Spec** section below for full frontend details.

- Uses `supabase.auth.signInWithPassword({ email, password })`
- Inline error messages
- No signup link, no social auth, no magic link
- After successful login: `router.push("/updates")` + `router.refresh()`

### Step 8: Create auth callback — `app/auth/callback/route.ts`

- Handles `?code=` param from password reset emails
- Exchanges code for session via `supabase.auth.exchangeCodeForSession(code)`
- Redirects to `/updates` on success, `/login?error=...` on failure

### Step 9: Add logout to TopNav — `components/top-nav.tsx`

See **Logout Button Design Spec** section below for full frontend details.

- Import `createClient` from `@/lib/supabase/browser`
- Import `useRouter` from `next/navigation`
- Import `LogOut` from `lucide-react` (already installed)
- Add logout button in the header's right side (after live badge)
- `supabase.auth.signOut()` → `router.push("/login")` + `router.refresh()`

## Supabase Dashboard Setup (per client project)

Before deploying, in each client's Supabase Dashboard:

1. **Auth → Providers → Email**: Ensure "Enable Email provider" is ON
2. **Auth → Settings**: Disable "Enable email confirmations" if you want instant access after invite
3. **Auth → Users → Invite User**: Create users with email — they receive a password setup link
4. **Table RLS**: Verify `rdn_new_updates` allows SELECT for `authenticated` role (or RLS is disabled)

## Adding Users for a New Client

1. Open the client's Supabase Dashboard
2. Go to **Authentication → Users**
3. Click **Invite User**
4. Enter the user's email address
5. User receives an email with a link to set their password
6. Once password is set, they can log in at the client's deployment URL

No code changes needed to add users.

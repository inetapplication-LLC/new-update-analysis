# v1.5 Real-Time Notifications — Setup Playbook

Step-by-step guide for setting up real-time in-app toasts and push notifications on any new client deployment.

---

## Prerequisites

### 1. Generate VAPID Keys

```bash
npx web-push generate-vapid-keys
```

Save the output — you'll need the public and private keys.

### 2. Environment Variables

Add these to `.env.local` (or your deployment environment):

```env
# Already required from v1.0
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon-key>

# VAPID keys for Web Push (from step 1)
NEXT_PUBLIC_VAPID_PUBLIC_KEY=<public-key>
VAPID_PRIVATE_KEY=<private-key>
VAPID_SUBJECT=mailto:support@yourcompany.com
```

### 3. `push_subscriptions` Table

If not already created, run this SQL in the Supabase SQL Editor:

```sql
CREATE TABLE IF NOT EXISTS push_subscriptions (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id uuid REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  endpoint text NOT NULL,
  p256dh text NOT NULL,
  auth_key text NOT NULL,
  user_agent text,
  created_at timestamptz DEFAULT now(),
  UNIQUE (user_id, endpoint)
);

-- Allow authenticated users to manage their own subscriptions
ALTER TABLE push_subscriptions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users manage own subscriptions"
  ON push_subscriptions
  FOR ALL
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);
```

## Supabase Configuration

### 1. Enable Realtime on the Updates Table

```sql
ALTER PUBLICATION supabase_realtime ADD TABLE rdn_new_updates;
```

Verify it's added:

```sql
SELECT schemaname, tablename
FROM pg_publication_tables
WHERE pubname = 'supabase_realtime';
```

### 2. RLS Policy for `rdn_new_updates`

If RLS is enabled on `rdn_new_updates`, ensure authenticated users can SELECT:

```sql
CREATE POLICY "Authenticated users can read updates"
  ON rdn_new_updates
  FOR SELECT
  USING (auth.role() = 'authenticated');
```

If RLS is disabled (default for this table), no action needed.

### 3. Deploy the Edge Function

The `send-push-notification` Edge Function is deployed via Supabase MCP or CLI.

**Via Supabase CLI:**

```bash
supabase functions deploy send-push-notification --project-ref <project-ref>
```

The function source is at the Supabase project level (not in this repo). Key behaviors:
- Receives webhook payload with the inserted row
- Reads all subscriptions from `push_subscriptions`
- Sends Web Push via `web-push` npm package
- Title: `"New {update_type} Update"`
- Body: First 120 characters of `update_content`
- Tag: Fixed `"aims-new-update"` so browser collapses rapid pushes
- Cleans up expired subscriptions (410 Gone responses)

### 4. Set Edge Function Secrets

```bash
supabase secrets set \
  VAPID_PUBLIC_KEY="<public-key>" \
  VAPID_PRIVATE_KEY="<private-key>" \
  VAPID_SUBJECT="mailto:support@yourcompany.com" \
  --project-ref <project-ref>
```

Note: `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` are automatically available in Edge Functions.

### 5. Create the Database Webhook

Create a PG function and trigger that fires the Edge Function on every INSERT:

```sql
-- Ensure pg_net extension is enabled
CREATE EXTENSION IF NOT EXISTS pg_net;

-- Create the trigger function
CREATE OR REPLACE FUNCTION notify_push_on_new_update()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
begin
  perform net.http_post(
    url := 'https://<project-ref>.supabase.co/functions/v1/send-push-notification',
    headers := jsonb_build_object(
      'Content-Type', 'application/json',
      'Authorization', 'Bearer ' || current_setting('app.settings.service_role_key', true)
    ),
    body := jsonb_build_object(
      'type', 'INSERT',
      'table', 'rdn_new_updates',
      'schema', 'public',
      'record', row_to_json(NEW)
    )
  );
  return NEW;
end;
$$;

-- Create the trigger
CREATE TRIGGER on_new_update_push_notification
  AFTER INSERT ON rdn_new_updates
  FOR EACH ROW
  EXECUTE FUNCTION notify_push_on_new_update();
```

Replace `<project-ref>` with your Supabase project reference ID.

**Alternative**: Use Supabase Dashboard > Database > Webhooks to configure this via UI:
- Table: `rdn_new_updates`
- Event: INSERT
- Type: Supabase Edge Function
- Function: `send-push-notification`

## Verification Checklist

### In-App Toast
1. Open the dashboard at `/updates`
2. In Supabase SQL Editor, insert a test row:
   ```sql
   INSERT INTO rdn_new_updates (case_id, update_type, update_date, update_content)
   VALUES (99999, 'Client', now()::text, 'Test notification from SQL editor');
   ```
3. A toast should appear within ~2 seconds, and the data should auto-refresh

### Push Notification (Background)
1. Enable push notifications via the bell icon in the nav
2. Close or background the tab
3. Insert another test row (same SQL as above)
4. A system notification should appear
5. Clicking it should open `/updates`

### Debounce (Bulk Inserts)
1. Open the dashboard at `/updates`
2. Run a bulk insert:
   ```sql
   INSERT INTO rdn_new_updates (case_id, update_type, update_date, update_content)
   SELECT generate_series(90000, 90009), 'System', now()::text, 'Bulk test ' || generate_series(1, 10);
   ```
3. Should show a single toast: "10 new updates received" (not 10 individual toasts)

### Cross-Day Toast
1. View a specific day (e.g., Monday)
2. Insert a row for a different day
3. Toast should include a "View" action button that switches to that day

### Subscription Cleanup
1. Manually set an endpoint to an invalid URL in `push_subscriptions`
2. Trigger an insert — the Edge Function should remove the expired subscription

## Troubleshooting

- **No toast appearing**: Check browser console for Supabase Realtime connection errors. Verify `rdn_new_updates` is in the `supabase_realtime` publication.
- **No push notification**: Check Edge Function logs in Supabase Dashboard > Edge Functions > send-push-notification > Logs. Verify VAPID secrets are set.
- **Push notification but no click action**: Verify the service worker (`sw.ts`) has the `notificationclick` handler registered.
- **Expired subscriptions not cleaning up**: Check Edge Function logs for 410 responses. The cleanup only fires when a push attempt returns 410 Gone.

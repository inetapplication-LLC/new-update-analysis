# v1.1 — Multi-Client Support

**Status:** Planned
**Version:** v1.1
**Date:** 2026-02-22

---

## Overview

Enable the same codebase to serve multiple clients through environment variables. Each client gets their own Vercel deployment pointing to this repo, with different env vars for client name and Supabase credentials. The app remains fully PVT-branded (colors, logo, design) — only the **display name** and **database** change per client.

---

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                    GitHub Repo                       │
│              (single source of truth)                │
└──────────┬──────────────┬──────────────┬────────────┘
           │              │              │
     Vercel Deploy  Vercel Deploy  Vercel Deploy
     (Demo)         (Client A)     (Client B)
           │              │              │
     No env vars    CLIENT_NAME=   CLIENT_NAME=
     → "Demo Co"    "Midnight…"    "Professional…"
           │              │              │
     Demo Supabase  Client A DB    Client B DB
```

### Key Principle

- **Same repo, same code, same design** across all deployments
- Only env vars differ per deployment
- Default behavior (no env vars) shows "Demo Company" with demo data

## Environment Variables

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `NEXT_PUBLIC_CLIENT_NAME` | No | `Demo Company` | Display name shown in header and context strip |
| `NEXT_PUBLIC_SUPABASE_URL` | Yes | — | Supabase project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Yes | — | Supabase anonymous/public key |

### Why `NEXT_PUBLIC_` prefix?

These values are used in client-side components (top nav, context strip). Next.js requires the `NEXT_PUBLIC_` prefix for env vars that need to be available in the browser.

## Implementation Details

### `lib/client-config.ts`

Single source of truth for client configuration. Reads from env vars with safe defaults:

```ts
export const clientConfig = {
  clientName: process.env.NEXT_PUBLIC_CLIENT_NAME ?? "Demo Company",
};
```

### Component Changes

Both `top-nav.tsx` and `context-strip.tsx` currently hardcode `"Midnight Express"`. These will import `clientConfig` and use `clientConfig.clientName` instead.

## Adding a New Client

1. Create a new Vercel project pointing to this repo
2. Set environment variables:
   - `NEXT_PUBLIC_CLIENT_NAME` = client's display name
   - `NEXT_PUBLIC_SUPABASE_URL` = client's Supabase URL
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY` = client's Supabase anon key
3. Deploy — the app will show the client's name and pull from their database

No code changes needed.
